# 文档规则

## 事实来源

1. 运行时行为高于界面文案，界面文案高于设计说明。
2. 已实现行为以 `Sources/` 与对应测试为准；依赖版本以 `Package.resolved` 为准。
3. 未发布的地址、版本和功能必须标为占位或未发布，不写成已上线事实。

## 编写要求

- 直接说明用户可以完成的任务、前置条件、结果和失败恢复。
- 每个概念只在负责它的文档中完整解释，其他位置使用链接。
- 命令必须可复制，路径使用仓库根目录相对路径；本机绝对路径只用于明确的本地开发入口。
- UI 名称与应用本地化保持一致，代码符号保留原名。
- 仓库首页以 `README.md` 为简体中文主文档，并为应用支持的其他语言保留完整 README；功能、前置条件、版本与权限事实必须同步，不能只翻译标题或摘要。
- 数据图必须注明事实来源，并提交可重复生成的脚本或命令；图中的数字不得手工补齐缺失记录。
- 不编造口号或用口号填充页面；可原文引用当前官网口号。不得加入占位功能、性能承诺或无法验证的安全声明。
- 不记录令牌、Cookie、密码、私钥、私有仓库正文或未经脱敏的日志。
- 协议文本与产品行为冲突时先修正事实，再由维护者复核协议。

## 修改检查

- 行为、设置、快捷键或错误恢复变化：更新 README 或应用内帮助。
- README 的事实变化：同步检查 `README.*.md`，并保留各语言之间可直接切换的入口。
- CHANGELOG 增加带日期的版本标题：运行 `./scripts/generate-update-curve.py`，同步检查更新曲线和版本表格。
- 架构边界变化：更新 `docs/ARCHITECTURE.md`。
- 依赖、签名、版本或发布流程变化：更新 `docs/RELEASING.md` 和第三方许可。
- 数据发送、保存或删除方式变化：复核隐私政策、用户协议和免责声明。
- 所有 Markdown 链接必须可解析；示例命令至少完成语法检查。
