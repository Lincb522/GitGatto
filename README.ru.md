GitGatto — нативный клиент Git и GitHub для macOS на Apple Silicon и Intel. Помимо работы с репозиториями, он предлагает копии незакоммиченного кода, журнал внешних Agents, цели поставки, поиск регрессий и настройку инструментов разработки.

<a id="why"></a>
## Зачем мы делаем GitGatto

После написания кода остаются смешанные изменения, регрессии, CI, ревью и релизы. При смене задачи легко потерять из виду черновики и файлы без коммита.

С Agents нужно ещё понять, что и зачем изменено, какие свидетельства остались после ошибки и работает ли объявленный готовым результат. GitGatto помогает разбирать и продолжать эту работу, а не просто добавляет кнопки к Git. Он использует системный Git и существующие CLI, сохраняя доступ к изменениям, свидетельствам и точкам восстановления.

<a id="features"></a>
## Особые возможности

<a id="recovery"></a>
### Копии незакоммиченного кода и наблюдение за внешними изменениями

Добавленные локальные репозитории копируются по расписанию, при крупных изменениях или вручную, без повторного сохранения одинакового содержимого. До трёх поколений на репозиторий включают Git bundle и незакоммиченные файлы.

Точку можно создать перед записью встроенного Agent. Защита также наблюдает удаления, потерю изменений, откат ссылок и недоступность репозитория после работы внешних Agents, терминалов или скриптов. Сообщение показывает причины и пути, но не доказывает вину конкретного процесса.

Поэтапная запись и метки завершения отделяют неполные копии после аварийного выхода от действительных. Можно смотреть объём, удалять отдельные копии или копии репозитория, переносить их при смене каталога. Восстановление создаёт новый каталог, не перезаписывает исходный. Это не системный перехватчик команд; восстановление несохранённых и исключённых файлов не гарантируется.

<a id="monitoring"></a>
### Состояние репозиториев в строке меню

Все репозитории или один выбираются независимо от главного окна: изменения, upstream, точки восстановления, Actions, цели и год ежедневной активности. Точки считают коммиты и наблюдаемые изменения, не рабочие часы.

Отдельные каналы рабочего дерева, удалённого состояния, защиты, Actions и целей, общий выключатель, видимость значка и интервалы находятся в настройках. Наблюдение продолжается при работе приложения в фоне и прекращается после выхода.

<a id="goals"></a>
### Продолжение цели поставки после перерыва

Выберите поставку текущих изменений, поставку через GitHub, полный релиз или цель на естественном языке. До создания проверьте шаги, после — прогресс, препятствия и записи. Доступны поиск и фильтры активных и прошлых целей.

Маршрут проверяет индекс, коммит, Push, PR, Review, Actions, артефакты, Release, DMG, Appcast и установленную версию. Предложенные Agent условия требуют подтверждения. После перерыва перечитывается реальное состояние; текст Agent не доказывает успех. Слияние, публикация тегов и установка подтверждаются отдельно.

<a id="intent"></a>
### Разделение смешанных изменений на коммиты

Группируйте файлы или hunks Diff с отдельными сообщениями, при желании с помощью Agent. Перед выполнением проверяются пропуски, повторы и изменение репозитория, создаётся точка восстановления, затем коммиты идут по порядку.

Каждый проходит проверку diff или заданную команду. При сбое предпринимается возврат к исходным HEAD и границе индекса, но успех отката в любой ситуации не гарантирован. Точка восстановления остаётся доступна.

<a id="regression"></a>
### Поиск регрессий в отдельном worktree

`git bisect` не переключает текущий рабочий каталог. Автоматическая проверка командой или ручные оценки «исправно», «сбой», «пропустить». Кандидаты, решения, коды выхода, время и вывод сохраняются.

Свидетельства можно передать Agent для исправления, повторной проверки и подготовки PR. Команда должна выявлять нужную ошибку; большое число пропусков может оставить несколько кандидатов.

<a id="evidence"></a>
### Происхождение кода, капсулы ошибок и журнал

- **Происхождение:** от строки к коммиту и, при доступной GitHub CLI, к связанным PR, issues, reviews и checks.
- **Капсулы:** базовый коммит, патчи, разрешённые неотслеживаемые файлы, сбойная команда, вывод и версии экспортируются в `.gatto`. Структура и хеши проверяются перед восстановлением отдельного worktree; вложенные команды автоматически не исполняются. Фильтруются только известные чувствительные пути и распознанное содержимое: проверьте перед отправкой.
- **Внешние Agents:** изменения файлов и ссылок связываются с известными Agent-процессами в каталоге репозитория с указанием силы свидетельств. Одновременная работа не доказывает авторство.

<a id="agent"></a>
### Agents не только для текста коммита

Codex CLI, Claude Code, Gemini CLI, OpenCode и собственные CLI. Встроенные Git-инструкции охватывают ревью индекса, черновики, конфликты, ветки, восстановление истории, состояние репозитория и релиз; к расследованию можно приложить исходные ошибки LFS, hooks, подписи и синхронизации.

Проект, перевод, поиск и установка используют отдельные каналы выполнения. Переписанный README сначала просматривается. Ответы Issue/PR создаются из обсуждения и diff, редактируются и отправляются только после подтверждения. Существующие настройки CLI и моделей сохраняются.

<a id="project-tools"></a>
### Контекст при переключении задач

**Рабочие состояния** сохраняют индексированные, неиндексированные и неотслеживаемые файлы, ветку, черновики, выбранный файл, цели и ссылки. При восстановлении проверяется состояние; можно открыть отдельный worktree. Игнорируемые файлы исключены, это не независимая резервная копия.

| Инструмент | Возможности |
| --- | --- |
| Поиск кода | Текущие файлы, ревизии и исторические изменения управляемых репозиториев; фильтры каталога, языка и расширения, просмотр и передача Agent. Буквальный поиск с ограничением результатов. |
| Запуск команд | Найти скрипты, добавить и закрепить команды; вывод, время, статус, остановка, повтор и локальные сервисы. Неинтерактивно, аргументы — JSON-массив. |
| Правила исключения | Показать источник, предварительно проверить `.gitignore` или `.git/info/exclude`; прекратить отслеживание, оставив файлы. |
| Идентификация коммитов | Автор и подпись для репозитория/каталога, действующий источник и проверка перед коммитом. Отдельно от входа GitHub. |

Открываются через инструменты проекта или `⌘K`.

<a id="install-tools"></a>
### Установка вместе с настройкой и проверкой

Каталог использует GitHub Releases, различая загрузку и установку. DMG/ZIP устанавливаются нативно, пакеты командной строки передаются Agent. Видны этапы, вывод и повтор.

**99 инструментов и сред выполнения**, определение локальных версий, множественный выбор и пакетное обновление. Очереди установки/обновления допускают три параллельные задачи; запись Homebrew последовательная.

Нужные PATH, регистрация плагинов, инициализация и перенос настроек предшествуют проверке исполняемого файла и версии. Загрузка или сообщение Agent не заменяет её. Незавершённые права/настройки остаются видимыми; вход и системное разрешение выполняет пользователь. Список установленных приложений отражает установки GitGatto, не весь Mac.

<a id="git-github"></a>
## Повседневный Git и GitHub

- Индекс, коммиты, diff, граф, blame, история файлов и медиа; комбинированный поиск SHA, автора, пути, текста, даты и ссылки.
- Ветки, теги, remotes, stash, worktrees, сравнение и восстановительные ветки из reflog. Перестановка, squash, разделение, amend, cherry-pick, revert, reset; проверка опубликованных коммитов до переписывания и подтверждение разрушительных операций.
- Конфликты merge/rebase/stash, продолжение, пропуск, отмена; диагностика LFS, hooks и инструментов.
- Fetch/pull/push нескольких репозиториев; отдельные результаты опережения, отставания, расхождения, конфликтов и ошибок, повтор неудачных.
- Репозитории аккаунта, поиск разработчиков и на естественном языке, Star, Fork, clone, код, README, releases и вложения.
- Входящие reviews, упоминания и неудачные checks; создание/обработка issues; файлы PR, отметки просмотра, построчные комментарии, ответы и reviews.
- Actions: запуски, логи, повтор, отмена, артефакты. Обновление страницы не запускает удалённую запись.

<a id="reading"></a>
## Чтение и перевод

Markdown, относительные изображения, исходники, SVG и медиа внутри приложения. Определение языка и отдельная конфигурация перевода; кеш по оригиналу, пути и целевому языку. Изменённый оригинал не получает старый перевод. Короткий текст или уже целевой язык может остаться без изменения. README автоматически не коммитится.

<a id="appearance"></a>
## Темы и интерфейс

Шесть тем: Легкий туман, Мягкое матовое стекло, Консоль, Изумруд, Фолио, Световая сцена. Меняются компоновка, панели, боковая область и элементы управления. Световая сцена отдельно настраивает светлые/тёмные цвета фона, панелей, текста, кнопок и состояний; варианты Коралл, Побережье, Лес, Сумерки.

Сворачиваемые прокручиваемые разделы, изменяемые размеры областей и 11 языков без перезапуска. Инструкции во встроенной справке.

<a id="start"></a>
## Установка и начало

Скачайте DMG из [Releases](https://github.com/Lincb522/GitGatto/releases/latest), перенесите в «Программы». macOS 14+, Apple Silicon/Intel. Выпущенные версии — в [Changelog](CHANGELOG.md) и Releases; README описывает текущий репозиторий.

| Задача | Требуется |
| --- | --- |
| Локальный Git и обычная синхронизация | Git и аутентификация Git / SSH удалённого репозитория |
| GitHub, PR, Issue, Actions | Авторизованная [GitHub CLI](https://cli.github.com/) |
| Agent, перевод, установка Agent | CLI с нужным входом/конфигурацией поставщика |
| Определение и обновление Homebrew | Homebrew |

Откройте репозиторий либо вручную просканируйте и выберите; автоматического импорта всего диска нет. GitHub и Agents — в настройках, обновления — через Releases и Appcast.

<a id="data"></a>
## Данные и разрешения

Списки, настройки, цели, расследования, диалоги, переводы, загрузки и восстановление хранятся локально; каталог копий переносится. Git, SSH и CLI используют свои источники учётных данных.

Локальное хранение не означает полностью офлайн: есть обращения к GitHub, необходимый контекст Agent/перевода передаётся выбранной CLI. Дальнейшая обработка зависит от инструмента и сервиса модели. Проверяйте отправляемое; не помещайте секреты в команды, черновики и капсулы. Системные каталоги требуют разрешения macOS.

<a id="development"></a>
## Запуск из исходников

macOS 14+, Swift 6.1+; настройки Xcode — `project.yml`.

```sh
git clone https://github.com/Lincb522/GitGatto.git
cd GitGatto
swift package resolve
swift test
swift run GitGatto
```

Либо `GitGatto.xcodeproj`, scheme `GitGatto`. После изменения структуры используйте XcodeGen и `./scripts/generate-xcodeproj.sh`, не редактируйте проект вручную. SwiftUI, AppKit, WebKit, AVKit, Alamofire, Sparkle; версии — `Package.resolved`.
